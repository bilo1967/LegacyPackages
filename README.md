# LegacyPackages

Controlled security backports for older Ubuntu/Debian packages. Work is isolated in GitHub Actions and Docker, not on production machines.

## Apache status (15 November 2026)

| Ubuntu | Base | Status |
| --- | --- | --- |
| 20.04 Focal | `apache2 2.4.41-4ubuntu3.23` | Active experimental backport on branch `backport/focal`. **Not released or production-approved**. |
| 18.04 Bionic | `apache2 2.4.29` (exact host revision unverified) | No implementation or build in this repository; decision documented below. |

**Focal:** the Jammy `2.4.52-1ubuntu4.27` patch inventory currently produces **63 imported candidates, 4 excluded**. There are also independent Focal-only compatibility changes and a native `mod_md` backoff fix. The experimental Debian package version is `2.4.41-4ubuntu3.23+unibo0~experiment1`. CI package builds and HTTP/PHP/MPM/module smoke tests passed through run **#84**. Run **#84** also passed the UBSan boundary test for the native `mod_md` backoff fix.

A green workflow means its defined tests passed, **not** that all applicable ESM vulnerabilities have been independently proven fixed. No packages from these workflows should be installed in production yet.

### Ubuntu 18.04: do not start a second broad backport by default

[Assessment and decision criteria](apache2/bionic-evaluation.md). **Bionic is affected by security updates in 2026**, including [USN-9090-1](https://ubuntu.com/security/notices/USN-9090-1), but several CVEs affecting Focal are explicitly absent on Bionic. The 20.04 workflow/tooling is reusable; the majority of **source-level adaptation work is not guaranteed reusable** against Apache 2.4.29.

Prefer (1) official Ubuntu Pro/ESM updates where available, (2) upgrading/replacing the host, or (3) migrating a suitable small web service to Caddy + PHP-FPM. Only consider a selective Bionic patch port if a small, demonstrably relevant vulnerability set remains and a quick exact-context dry run succeeds. Do not begin a second 63-patch port.

## Rules

Preserve distro packaging and module ABI; do not silently change MPMs or overwrite third-party modules. Validate CVE applicability against the **actual release and enabled features**. Preserve vendor patch ancestry and relevant regression follow-ups. Use disposable release-matched build/test containers. Publish a manifest of applied/skipped patches. Check resulting packages, module load and behavior before a staged rollout. Keep rollback artifacts, test configuration and production snapshots separately.

Do not commit private keys, certificates, credentials, secrets, personal data or production vhost configurations. For public release, evaluate distribution/licensing and source provenance, package signing and APT repository trust.
